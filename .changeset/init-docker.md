`sabit init` asks for a database and ORM (PostgreSQL with Prisma, Drizzle or Kysely; MongoDB with Mongoose, Typegoose or Prisma 6, since Prisma 7 can't connect to MongoDB yet) and generates the connection, a users model, a generic repository in `src/db/repository.ts` (`createRepository(...)` per model; an empty `*.repository.pattern.ts` is filled with one by `sabit dev` / `sabit watch`) and /users endpoints that use it. It also offers Redis, BullMQ, Kafka, RabbitMQ and email (Mailpit) clients, and Docker: one multi-stage Dockerfile (a dev stage for live reload, a lean production stage) and a docker-compose.yml with the chosen services. New flags: `--db`, `--orm`, `--with`.

Every scaffolded route (`sabit init`, `sabit add`, a new folder while `sabit dev` runs) now gets a Vitest test in `test/routes/`, run with `npm test`. Starters include Vitest; Fastify starters read `HOST`. In-memory sample data now uses random ids, so items created in the same millisecond no longer collide.

`src/env.ts` is generated: `ENV` has an entry for every key in `.env` and `.env.example`, kept in sync by `sabit dev` / `sabit watch` and written by `sabit generate`. Projects with Docker Compose get `docker:up` and `docker:down` scripts.

Every starter's server entry now logs each request and sets security headers and CORS (any origin unless `CORS_ORIGIN` lists them): Express with morgan, helmet and cors; Hono with its logger, secureHeaders and cors; Fastify with its logger, @fastify/helmet and @fastify/cors; NestJS with an HTTP logger, helmet, `enableCors`, a global `ValidationPipe` and shutdown hooks.

`sabit watch` and `sabit dev` no longer print a banner; the watcher only reports the files it changes, and the VS Code task runs it without showing its terminal.

Routes declare who may call them with an `auth` export (`true`, a role, roles, or per method: `{ POST: true, DELETE: "admin" }`), checked by the `guard()` in src/middleware.ts, whose `rules` are now optional. A route exporting `auth` without a guard fails at startup instead of staying public. Generated routes use it, and the starter middleware only says who is calling.

`sabit dev` (and so `docker:up`) brings the database in line with the schema before starting the server and again whenever the schema changes: Prisma creates and applies migrations (`db push` for MongoDB) and generates its client, Drizzle generates and applies migrations, Kysely applies pending ones. New Prisma and Drizzle migrations are named after what they change (`init`, `create_posts`, `add_nickname_to_users`, `remove_age_from_users`, two changes joined, more shortened to `..._and_more`) and kept in prisma/migrations and drizzle/. A database that isn't running is reported without stopping the server; one whose migrations come from another project (a reused Docker volume) gets a hint to reset it. In docker-compose.yml the app waits for a healthy Postgres or MongoDB.

Security: every adapter now uses `@sabit/adapter-common`, so file routes answer unexpected errors with a plain JSON 500 (the error goes to an `onError` option, by default `console.error`, never to the client), are rate limited per IP (100 requests a minute by default, `rateLimit` option) and refuse bodies over 100 KB with 413 (Hono and Fastify now match Express and NestJS). Starters take CORS origins from `corsOrigin()`, which requires `CORS_ORIGIN` in production; docker-compose.yml publishes ports on 127.0.0.1 only; the production image runs as the `node` user; the starter middleware compares tokens in constant time.

The router enforces a route's `auth` export itself, with the user any middleware puts on `ctx.state.user` (401 without one, 403 without the role), so `guard()` is no longer required and protected routes fail closed. The starter `src/middleware.ts` is a plain Express-style middleware that signs the caller in; an empty `middleware.ts` (in src/ or any routes folder) is filled with a starter by `sabit dev` / `sabit watch` and runs for that folder's routes.

The starter `src/middleware.ts` keeps one access list of every route, typed with `RoutePattern` from sabit.route.ts, and applies it with the new `checkAccess(ctx, rule)` from @sabit/router. New routes (`sabit add`, a new folder, `sabit init`) are added to that list instead of getting an `auth` export; a route deleted while still listed fails typecheck.

The access list shows every route: `/` and hand-written routes are added as public (`false`) by `sabit dev`, `sabit watch`, `sabit add` and `sabit generate`. 401 answers say "Sign in to use this route" with `WWW-Authenticate: Bearer` (the starter answers an invalid token with "Invalid or expired token"); 403 answers say permission is missing without naming the role. @sabit/router exports `unauthorized()` and `forbidden()`.

Import aliases instead of ../../ paths: starters declare `#src/*` and `#test/*` in package.json "imports" (Node's own aliases), and generated code uses them (`sabit add` keeps relative paths in projects without them). Express, Hono and Fastify builds type-check with tsc and bundle with tsup into dist/; NestJS keeps `nest build`, with `#src/*` pointing at dist/ at runtime. The Prisma client is generated into prisma/generated and imported as `#prisma/generated/client` (src/generated in NestJS, which compiles only src/).

Authentication: `sabit init` asks "Add authentication?" (flag `--auth jwt`). Custom JWT adds src/auth.ts and POST /auth/register, /auth/login, /auth/refresh, /auth/logout and GET /auth/me: passwords hashed with scrypt, a 15-minute access token and a 30-day refresh token in HttpOnly SameSite=Lax cookies (Secure in production; `Authorization: Bearer` also works), refresh tokens stored as SHA-256 in the database (a RefreshToken model for Prisma, Drizzle, Kysely, Mongoose, Typegoose, or in memory without a database), rotated on every refresh, with every session of an account ended when a spent token is replayed. Accounts register with name, email and password and sign in with email and password. The first admin account, admin@example.com / 12345678, is created on the first start outside production, only while no admin exists, so a changed email or password stays; it isn't configured in .env. /users becomes admin-only account management that never returns password hashes. Repositories gain `findOne` and `deleteMany`.

New `sabit setup`: `sabit init` now makes a plain project and asks one question, "Add a database, auth, Redis, queues, email or Docker now?"; the same menu is available later with `sabit setup` (or `sabit setup auth docker`, with `--db`, `--orm`, `--auth`, `--with`, `--no-install`). It shows only what the project doesn't have yet, writes the files, updates package.json and .env, installs and prints next steps; init's next steps point to it. sabit.json records the features and a fingerprint of each file sabit wrote: a file you changed is never overwritten, and sabit's version is written next to it as `<file>.sabit-new`. Every project has `src/auth/index.ts`, which src/middleware.ts uses to sign the caller in, so adding auth later only replaces what's in src/auth/.

Better Auth: `sabit setup auth` (or `--auth better-auth`) now offers Better Auth next to Custom JWT. It needs a database (it asks for one, or `--db`), uses the project's ORM through Better Auth's adapter (Prisma on PostgreSQL or MongoDB, Drizzle, Kysely, Mongoose, Typegoose) with users, sessions, accounts and verifications tables, has the same routes as Custom JWT, one folder each: POST /auth/register, /auth/login, /auth/logout and GET /auth/me, each running its Better Auth endpoint (`src/auth/handlers.ts`), signs in by email and password with database sessions in an HttpOnly cookie or `Authorization: Bearer`, creates the first admin like Custom JWT, and makes /users admin-only account management through its admin API. Generated tests keep Better Auth's data in memory.

Auth code lives in `src/auth/`: `index.ts` (what routes and middleware import), `session.ts`, `seed.ts`, and one helper per file in `utils/` (JWT: password, jwt, cookies, refresh-token, public-user; Better Auth: request, errors), with `handlers.ts`, plus `better-auth.ts` and `database.ts` for Better Auth. `sabit setup` moves projects with the older `src/auth.ts` and `src/db/seed.ts` there and repoints their imports. The NestJS starter no longer emits declaration files.

API docs: built into the router, not a folder in src/routes. Every project serves Swagger UI at /docs and the OpenAPI 3.1 document at /docs/openapi.json, built from the loaded routes (paths, params, `schema.ts` bodies as JSON Schema, and which routes the access list protects), so new and changed routes appear as soon as the dev server reloads. Off in production unless `API_DOCS=true`. Routes can export `docs` (summaries per method and tags, or `false` to hide). The URL /docs is reserved: a top-level `src/routes/docs` folder is an error, `sabit add docs` refuses, and `sabit dev` removes a new empty one; nested folders such as products/docs are fine. @sabit/router adds `apiDocs` to `RouteSources` (the generated route tree turns it on), `openApiDocument()`, `apiDocsPage()` and `apiDocsEnabled()`, and resolved routes carry their `bodySchema`; src/middleware.ts exports its access list. `sabit setup` removes the docs routes and the Better Auth catch-all an earlier version wrote.

The access list in src/middleware.ts now follows deleted routes too: `sabit dev`, `sabit add` and `sabit generate` remove the entries of routes that no longer exist (nothing changes while the routes have errors).
